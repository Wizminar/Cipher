      How it works

      The formula everyone quotes is too generous

      The usual measure of strength is length × log₂(pool): a 13-character password using all four character types gets about 85 bits. That's only true if every character were picked at random. People don't do that, and attackers know it.

      Cracking tools start with leaked password lists, dictionaries, names, years and keyboard runs, then apply rules like capitalising the first letter or swapping a for @. So Cipher looks for every one of those patterns, gives each an estimated guess count, and then searches for the cheapest way to split the password into pieces:

      guesses = k! × (guesses for piece 1 × … × piece k) + 10000k−1

      The k! covers the different orders the pieces could appear in. The last term stops the search from chopping a password into lots of tiny cheap pieces. This is the approach behind Dropbox's zxcvbn, rewritten here from scratch with its own lists and tests.

      Checking a breach list without revealing the password

      Sending your password to a server to ask "has this leaked?" would be a leak in itself. The Pwned Passwords range API uses k-anonymity instead:

      1. Your browser hashes the password with SHA-1.
      2. Only the first 5 characters of the hash are sent. Around a million passwords share any given 5-character prefix.
      3. The API sends back every breached hash with that prefix, usually 800 to 1,000 of them, padded with decoys so the response size reveals nothing either.
      4. Your browser looks for the rest of the hash in that list. The answer never leaves the page.

      Cipher only checks when you ask. Checking automatically as you type would send a prefix for every version you paused on (d, dr, dra…). Anyone watching could then try each possible next character until the next prefix matched, and rebuild the password one character at a time.

      SHA-1 is used here only because it's the format the API expects. It would be a bad choice for storing passwords, which is exactly why the next point matters.

      Crack time depends on the website too

      The same password can survive for centuries or fall in minutes depending on how the site stores it. A login form with lockouts allows a few guesses an hour. A stolen database of bcrypt hashes allows thousands a second. Unsalted MD5 or SHA-1 lets a rig of GPUs try a hundred billion a second. Cipher shows all four, because you can't know which kind of site you're trusting.

      Honest limitations

      Estimates are only as good as the lists behind them: about 10,000 common passwords, 9,500 English words and 4,900 first names. Real attackers have bigger lists and personal context like your pet's name, so treat any score as an upper bound. Attack rates are round figures for realistic setups, not measurements of any specific attacker.
